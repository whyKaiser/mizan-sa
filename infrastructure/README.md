# إعداد الخدمة السحابية

البيئة مفعلة ومختبرة منذ 28 سبتمبر 2026 على مشروع `mizan-sa` المخصص، بالخطة المجانية. لا تُطبّق المخطط على مشروع آخر مستخدم لغرض مختلف.

1. أنشئ مشروع Supabase مخصصًا باسم ميزان بعد اعتماد المؤسسة والتكلفة.
2. نفّذ `schema.sql` في المشروع. لا توجد فيه بيانات شخصية أو كلمات مرور.
3. تحقق من أن RLS مفعلة وأن الزائر `anon` لا يملك صلاحيات جدول المشاريع. السياسات تسمح للمستخدم فقط بصفوف `user_id = auth.uid()`.
4. اضبط Site URL على رابط Pages النهائي، وروابط العودة المسموحة على هذا العنوان بالضبط؛ أضف localhost للتطوير عند الحاجة فقط.
5. إعداد النسخة التعليمية المعتمد: Email provider مفعّل، Allow new users مفعّل، Confirm email معطّل. كلمة المرور 8 أحرف على الأقل مع أحرف إنجليزية وأرقام. Secure password change وRequire current password مفعّلان. لا SMTP ولا استعادة بريدية؛ لا تعد المستخدم بوصول رسائل. تعطيل التأكيد يعني أن العنوان ليس إثباتًا لملكية البريد، ولذلك لا تُستخدم بيانات حساسة.
6. انسخ عنوان الخدمة ومفتاح Publishable العام إلى `src/config.js`. لا تنسخ أي Secret Key أو service_role إلى الواجهة.
7. أعد البناء والنشر ثم اختبر حسابين تجريبيين مستقلين: إنشاء مشروع في A؛ عدم ظهوره لحساب B؛ رفض B لقراءة/تعديل/حذف معرف مشروع A؛ منع إضافة صف باسم مالك آخر.
8. اختبر تسجيل الدخول بكلمة مرور خاطئة، الحصول على جلسة مباشرة بعد التسجيل، الخروج، العودة من جلسة مستقلة، وتعارض تحديث نسختين. اختبر تغيير كلمة المرور بمعرفة الحالية، وفشل القديمة ونجاح الجديدة. شاشة النسيان تشرح عدم وجود استعادة بريدية.
9. شغّل مستشار الأمان والأداء، ووثّق النتائج الفعلية قبل تغيير حالة الجاهزية في README والدليل.

الحفظ السحابي لا يخزن كلمة المرور في جدول المشروع. الاسم الكامل للعرض في بيانات المستخدم لا يمنح أي صلاحيات. قيود JSONB تمنع حمولة ضخمة وهوية مشروع مخالفة؛ لا تجعل حسابات المستخدم سجلات محاسبية معتمدة.

## الاختبارات الحقيقية

`verify-rls.sql` يختبر CRUD وعزل مالكين ومنع تبديل المالك والحمولات المخالفة داخل معاملة تنتهي بـ ROLLBACK. `node infrastructure/verify-cloud.mjs` اختبار تكامل صريح ينشئ حسابين اصطناعيين في مشروع الاختبار المحدد ويفحص المسار نفسه المستخدم في الواجهة. ليس جزءًا من `npm test`، لأنه يُحدث بيانات على الخدمة. راجع معرفي الحسابين الناتجين وأزل هذين الحسابين فقط بعد الاختبار، مع مطابقة علامة `mizan_test_run`. بيانات اختبار المتصفح المؤقتة في `.local/cloud-qa-session.json` مستثناة من Git؛ لا تنشرها أو تعاود استعمالها بعد التنظيف.

تم إثبات الاختبارين على الخدمة، مع جلسات JWT حقيقية، ولم يظهر مستشار الأمان تنبيهات وقت الفحص. هذه نتيجة محددة وليست شهادة أمان شاملة.

## المجانية والتسليم

GitHub Pages في المستودع العام وSupabase Free فقط؛ لا اشتراك SMTP ولا إضافة مدفوعة. حدود Free تشمل 500 MB لقاعدة البيانات و5 GB نقل بيانات ضمن شروط الخدمة وقت الإعداد، وإيقافًا محتملًا بعد أسبوع خمول. لا تتوفر نسخ احتياطية تلقائية بالخطة المجانية. قبل العرض افتح المشروع وتحقق من نشاطه. أي زيادة تتطلب قرارًا جديدًا؛ لا ترقِّ الخطة دون موافقة صريحة.

بعد نقل GitHub، تبقى قاعدة البيانات في مؤسستها الحالية حتى تُنقل إلى مؤسسة تديرها المستلمة. لا تنشئ خلفية أخرى ولا تنقل إلى منظمة غير معتمدة. عنوان Site URL الحالي هو `https://alrajhylmy909-dev.github.io/mizan-sa/`، ولا يحتاج تدفق كلمة المرور المعتمد روابط بريد أو OAuth.

المخطط قابل لإعادة التطبيق دون حذف المشاريع؛ يعيد تعريف سياسات هذا الجدول. عند الانتقال إلى تطوير جماعي منتظم، أدر التغييرات عبر Supabase CLI ومراجعة migrations.
